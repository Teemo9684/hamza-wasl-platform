# همزة وصل — فصل التطبيقات الثلاثة

## مرحلة التنفيذ الأولى (فرع العمل فقط)

تستعمل التطبيقات الثلاثة كوداً مشتركاً وواجهات وصلاحيات موجودة بالفعل في المشروع، مع اختيار واجهة واحدة لكل إصدار.

| التطبيق | وضع البناء | الصفحة الافتراضية | نطاق الواجهة |
| --- | --- | --- | --- |
| الأولياء | `VITE_APP_AUDIENCE=parent` | `/` | الأولياء فقط |
| الأساتذة | `VITE_APP_AUDIENCE=teacher` | `/` | الأساتذة فقط |
| الإدارة | `VITE_APP_AUDIENCE=admin` | `/` | الإدارة فقط |
| تجربة 1.2.75 القديمة | متغير غير محدد | `/` | الواجهة المشتركة القديمة |

البناء: `npm run build:parent` أو `npm run build:teacher` أو `npm run build:admin`؛ كلها تنتج `dist/` بشكل منفصل. لا تنشر ناتج بناء فوق إصدار آخر.

## الأمان والعزل

- هذه المرحلة لا تنشئ حسابات ولا تغيّر جداول أو سياسات Lovable Cloud.
- القيود على المسارات في الواجهة **ليست** بديلًا عن صلاحيات قاعدة البيانات (RLS)؛ يجب التحقق منها قبل التشغيل الفعلي.
- لا تنشر التطبيقات الثلاثة على نفس النطاق أو بنفس إعداد خدمة التحديث.
- يجب تجهيز ثلاثة نطاقات ومشاريع نشر منفصلة، ومعرّفات Android مستقلة وقنوات OTA منفصلة قبل نشر APK.
- فرع `testing/android-pilot` وقناة `pilot-updates` و`main` غير متأثرين بهذه المرحلة.
- **حسابات الأساتذة**: واجهة التسجيل الذاتي مخفية في تطبيق الأساتذة المنفصل وفق القرار الجديد؛ آلية إنشاء الحساب من الإدارة تحتاج تنفيذًا واختبارًا قبل إطلاقه.
- الاختبارات التي تكتب بيانات يجب أن تكون في بيئة قاعدة بيانات اختبار منعزلة مع بيانات اصطناعية، لا في قاعدة بيانات المدرسة الحية.
- اسم وشعار المدرسة والألوان الحالية مشتركة بين التطبيقات.
